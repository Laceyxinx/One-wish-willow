# One Wish Willow 产品迭代复盘

## 1. 迭代背景

项目最初面向海外部署，首版系统 Prompt 主要使用英文编写。它能够让 `deepseek-v4-flash` 生成黑色幽默结果，但对中文用户的适配不足。

早期朋友试玩暴露出三个问题：

- 中文表达不够自然，存在英文逻辑直译的感觉；
- 结果偏长，不适合移动端快速阅读和分享；
- 不同愿望被统一处理成较重的恐怖结果，没有区分剧情型愿望与朋友间的娱乐愿望。

部分用户体验一次后认为结果“不对”，没有继续使用。这表明生成质量不是单纯的文案问题，而是会直接影响产品留存与传播。

## 2. 问题诊断

首版 Prompt 的主要问题不是模型能力不足，而是产品规则表达不完整：

| 问题 | 原因 | 用户影响 |
|---|---|---|
| 中文不够通顺 | 英文 Prompt 主导模型的表达结构 | 降低沉浸感和可信度 |
| 输出过长 | 未针对中文移动端阅读限定长度 | 揭晓节奏拖沓，不利于分享 |
| 反转随机或过度黑暗 | 强调“恐怖”，但没有充分约束因果关系和使用情境 | 用户认为结果与愿望无关 |
| 中英混合时语言判断错误 | 仅有简单的“输入什么语言就输出什么语言”规则 | 含英文人名的中文愿望可能错误输出英文 |

## 3. Prompt 本地化与规则迭代

针对以上问题，第二版在英文基础规则上加入中文场景规则：

### 3.1 语言本地化

- 中文愿望必须输出自然中文，而不是英文句式直译；
- 英文愿望输出英文；
- 中英混合输入根据主要语义判断语言；
- 中文句子中的英文人名不应改变输出语言，例如“Nikki 爱我胜过任何人”仍应输出中文。

### 3.2 长度与可读性

- 将最终结果控制在约 100 字以内；
- 删除解释、标签、引言和多余铺垫；
- 保留“愿望已实现—实现方式—意外代价”的最小叙事结构。

### 3.3 结果因果性

- 必须先明确实现愿望，不能直接跳到惩罚；
- 后果必须来自原始措辞、隐藏假设或未限定边界；
- 避免与愿望无关的随机灾难；
- 目标感受是“这确实是我许的愿，但不是我想要的结果”。

### 3.4 场景分层

- 爱情、人生目标等剧情型愿望可以采用更强的一愿柳式代价；
- “朋友请我吃饭”等明显的社交娱乐愿望，调整为轻量、搞怪的结果；
- 避免所有愿望都落入死亡、世界毁灭等单一答案。

## 4. Prompt 前后对比

由于早期没有保存完整的逐条模型输出，以下记录的是已观察到的问题与优化方向，不将其伪装成逐字实验数据。

| 愿望类型 | 首版结果问题 | 优化后目标 | 修改依据 |
|---|---|---|---|
| 希望某人爱我 | 随机恐怖、因果关系弱 | 爱被极端兑现，并产生直接后果 | 对齐 Bear 与 Nikki 的电影设定 |
| 希望考上名校 | 只强调灾难，没有先实现愿望 | 明确录取，再由实现方式产生代价 | 强化“先实现愿望” |
| 朋友请我吃饭 | 结果过度黑暗 | 调整为适合朋友传播的搞怪反转 | 匹配实际使用情境 |
| 含英文人名的中文愿望 | 可能错误输出英文 | 按主要语义输出自然中文 | 改进混合语言判断 |
| 中文长句 | 输出冗长、阅读负担高 | 控制在约 100 字内 | 适配移动端揭晓和分享 |

## 5. 结果

- 中文结果的流畅度、长度和场景匹配度得到改善；
- 输出更接近“一愿柳会实现愿望，但结果未必如愿”的产品规则；
- Prompt 优化后，观察到 API 请求增长速度明显加快；
- 截至统计截图，累计产生 **326 次 API 请求、处理 262,855 Tokens**。

以上是模型调用数据，不等同于独立用户数、留存率或转化率。由于没有保存 Prompt 修改前后的分日请求数据，目前不能计算准确的增长幅度。

## 6. 产品结论

1. **Prompt 是产品逻辑，不只是技术配置。** 规则表达不清会直接造成用户认为产品“不对”。
2. **语言本地化不等于翻译。** 中文用户需要符合中文表达、阅读节奏和社交语境的结果。
3. **生成质量会影响传播。** 对娱乐产品而言，相关性、简洁度和可分享性共同决定用户是否愿意再玩。
4. **发布后仍需持续评测。** 后续应将 Prompt 版本、结果评分和行为指标关联起来。

## 7. 下一步验证

- 为每次 Prompt 修改记录版本号、日期和变更内容；
- 建立至少 50 条中英文固定愿望评测集；
- 收集“相关 / 意外 / 好笑 / 太黑暗”轻量反馈；
- 统计独立访客、结果完成率、重玩率和分享率；
- 比较 Prompt 修改前后各 7 天的请求量和用户行为。
