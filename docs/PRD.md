# One Wish Willow 产品需求文档（PRD）

## 1. 产品概览

| 项目 | 内容 |
|---|---|
| 产品定位 | 受电影《痴迷》（*Obsession*）启发的非官方 AI 许愿互动网站 |
| 核心规则 | 愿望一定实现，但结果未必是许愿者真正想要的 |
| 当前阶段 | 已上线 MVP / 作品集项目 |
| 全球部署 | `main` → Vercel |
| 中国大陆部署 | `腾讯云` → 腾讯云 |

影片中，Bear 使用一愿柳许愿 Nikki 爱自己胜过任何人。愿望实现后，Nikki 的爱走向病态，并引发一系列悲剧。本产品把这一设定转化为可参与的数字体验：用户许下愿望、折断柳枝，由 AI 告知愿望如何成真，以及随之而来的意外后果。

> 产品不是随机制造厄运，而是让用户发现：危险可能就藏在自己的愿望里。

## 2. STAR 产品逻辑

### S — Situation：为什么做

- 《痴迷》受到关注后，一愿柳成为具有讨论度和参与想象空间的电影道具。
- 观众会自然产生“如果是我，会许什么愿”的代入，但现有参与方式主要停留在观看和讨论。
- 普通 AI 输入框无法还原开盒、折断和愿望不可撤回的仪式感。
- 全球与中国大陆访问环境不同，需要两套部署路径保证可达性。

**机会判断：** 借助已有电影认知降低教育成本，用生成式 AI 为每个愿望提供个性化结果，把短期话题关注沉淀为可体验、可展示的产品。

### T — Task：要解决什么

1. 让首次访问者无需注册，并在 60 秒内完成一次许愿。
2. 让愿望真实实现，且意外后果必须与原始措辞存在因果关系。
3. 用交互营造“选择已不可撤回”的紧张感。
4. 模型异常时仍完成结果揭晓，不中断叙事。
5. 支持中英文及全球、中国大陆两种访问场景。

**非目标：** 不做通用聊天助手、账号系统、公开愿望社区或真实许愿服务。

### A — Action：如何实现

- 将体验拆为“开盒—许愿—折断—等待—揭晓”五个阶段。
- 用长按折断代替普通提交按钮，通过弯曲、裂纹和音效建立不可逆感。
- 制定“一愿柳生成规则”：先实现愿望，再从未限定的边界、规模或实现方式中推导代价。
- 根据输入语言输出结果，并为模型失败配置本地降级文案。
- 通过服务端接口调用模型，避免在浏览器暴露 API Key。
- 使用 Vercel 与腾讯云双分支部署，覆盖不同地区。

### R — Result：当前结果

- 已交付并上线可运行 MVP，核心许愿链路完整。
- 已接入 DeepSeek `deepseek-v4-flash`，并实现中英文生成、模型异常降级、移动端适配、键盘操作与减少动态效果支持。
- 已建立全球与中国大陆双部署方案。
- 上线初期根据朋友试玩反馈发现生成结果偏离产品设定，随后迭代 Prompt，结果相关性提升后，API 请求增长速度出现明显加快。
- 截至统计截图，累计产生 **326 次 API 请求、262,855 Tokens**。API 请求不等同于独立用户；由于缺少分阶段时间窗口，暂不计算或宣称具体增长率。

## 3. 目标用户

### 核心用户：关注《痴迷》且喜欢互动体验的年轻用户

这是一组结合画像，不拆分为两类：

- 看过或关注《痴迷》，对一愿柳设定感兴趣；
- 同时喜欢恐怖、黑色幽默、互动网页或生成式 AI；
- 想知道“如果由我许愿，会发生什么”；
- 偏好无需注册、移动端可快速完成的轻量体验；
- 愿意分享或讨论个性化结果。

### 作品集阅读者

招聘方、产品经理和设计同行，用于评估从热点洞察到产品交付的完整能力。

## 4. 价值主张

> 把电影中只能旁观的一愿柳，变成用户可以亲自许愿、亲自承担结果的互动体验。

| 差异点 | 用户价值 |
|---|---|
| 电影设定 | 熟悉的叙事入口，降低理解成本 |
| 单次愿望 | 强化选择的重量与稀缺感 |
| 折断仪式 | 让提交行为具有情绪和不可逆性 |
| AI 个性化 | 每个后果都来自用户自己的愿望 |

## 5. 用户故事

- 作为电影观众，我希望亲自体验一愿柳，而不只是观看 Bear 的选择。
- 作为首次访问者，我希望立即理解玩法，无需注册。
- 作为用户，我希望结果与我的愿望直接相关，而不是随机恐怖文案。
- 作为中英文用户，我希望获得同语种结果。
- 作为移动端或键盘用户，我希望完整完成折断和揭晓流程。
- 作为网络不稳定的用户，我希望模型失败时仍看到结局。

## 6. 核心流程

| 阶段 | 用户行为 | 系统反馈 | 目的 |
|---|---|---|---|
| 开盒 | 点击盒子 | 展示柳枝与音效 | 建立世界观 |
| 许愿 | 输入文本 | 校验并保存 | 获取个性化输入 |
| 折断 | 长按柳枝 | 弯曲、裂纹、声音 | 建立不可逆感 |
| 等待 | 无操作 | “柳枝正在聆听” | 管理生成延迟 |
| 揭晓 | 阅读结果 | 愿望成真及其代价 | 完成叙事闭环 |

## 7. MVP 功能需求

### P0

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-01 | 开盒引导 | 点击盒子或按钮均可进入许愿阶段 |
| FR-02 | 愿望输入 | 支持中英文；空输入不可提交；前后端限制长度 |
| FR-03 | 长按折断 | 支持触屏、鼠标和键盘；中途松开可回弹 |
| FR-04 | AI 结果 | 愿望必须实现；后果源于措辞或隐含假设；同语种输出 |
| FR-05 | 异常降级 | 模型失败或空返回时显示本地结果，不暴露技术错误 |
| FR-06 | 结果与重置 | 展示结局和彩蛋；可正确重置全部状态 |

### P1

- 漏斗与性能监测；
- 输入、输出安全审核；
- API 超时、限流和滥用防护；
- 隐私安全的结果分享卡；
- 双部署版本一致性检查。

## 8. AI 生成规则

Bear 的愿望是判断基准：Nikki 确实爱他胜过任何人，但愿望没有限定爱的健康程度和边界。

当前生成模型为 DeepSeek `deepseek-v4-flash`。首版 Prompt 对“一定实现愿望”和“后果必须来自原始措辞”的约束不足，导致部分试玩者认为结果“不对”。根据反馈完成 Prompt 迭代后，输出更贴近一愿柳设定，并观察到 API 请求增长加快。因此，Prompt 质量既是内容质量问题，也是影响用户继续体验与传播的核心产品变量。

首版以英文 Prompt 为主，对中文用户出现表达不自然、结果过长和使用情境不匹配的问题。第二版增加中文本地化规则：按照主要语义判断输出语言、中文结果控制在约 100 字内、先兑现愿望再揭示代价，并对朋友间的娱乐愿望采用更轻量的反转。完整复盘见 [PRODUCT_ITERATION.md](./PRODUCT_ITERATION.md)。

模型必须按以下顺序处理：

1. 识别用户想得到的结果；
2. 找到未说明的边界或隐藏假设；
3. 明确让愿望实现；
4. 推导与愿望直接相关的意外代价；
5. 使用第二人称、同语种和简洁表达。

禁止随机灾难、无关悲剧、露骨血腥、色情、自伤鼓励或针对现实人物的伤害内容。

### 输出质量标准

每项按 1–5 分评估：

- **愿望实现度：** 是否明确兑现请求；
- **因果相关性：** 后果是否来自原始措辞；
- **意外性：** 是否产生“技术上确实实现了”的反应；
- **清晰度：** 是否一遍可理解；
- **语言与安全：** 是否语种匹配并符合内容边界。

建议建立至少 50 条固定双语愿望作为回归评测集。

## 9. 非功能需求

- **性能：** 首屏轻量；生成期间立即展示等待状态。
- **安全：** 密钥仅保存在服务端；增加输入校验、限流和输出审核。
- **隐私：** 默认不持久化愿望；若引入分析需披露用途与保留周期。
- **无障碍：** 支持键盘、焦点状态和 `prefers-reduced-motion`。
- **一致性：** Vercel 与腾讯云版本共用产品逻辑和评测基线。

## 10. 指标与验证

### 北极星指标

**有效愿望体验完成数：** 完成输入、折断并看到结果的会话数量。

### 核心指标

- 首屏 → 开盒 → 提交 → 折断 → 结果的分步完成率；
- AI 成功率、降级触发率及 p50/p95 响应时间；
- 愿望实现度、因果相关性和语言匹配评分；
- 重玩、彩蛋点击和分享意愿；
- 全球与中国大陆部署的可用性差异。

### 建议目标

- 结果展示成功率 ≥ 99%（含降级）；
- 模型正常响应率 ≥ 95%；
- 语言匹配准确率 ≥ 95%；
- 移动端核心流程无阻断。

以上是待验证目标，并非已取得的结果。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| 输出失控或提示词注入 | 固定系统规则、输入/输出审核、回归评测 |
| 模型接口波动 | 超时、限次重试、降级结果和监控 |
| 双分支体验漂移 | 变更清单、共享评测集和 smoke test |
| 愿望含个人信息 | 默认不存储、日志脱敏、隐私声明 |
| IP 与官方品牌混淆 | 明确标注非官方粉丝项目，避免授权或商业背书暗示 |

## 12. 上线验收

- 新用户可在 60 秒内完成全流程；
- 桌面端、移动端和键盘均可完成折断操作；
- 中文愿望输出中文，英文愿望输出英文；
- 模型失败时仍展示安全、可读结果；
- 浏览器端无法读取模型 API Key；
- 两个部署分支通过同一组核心流程测试。
